# Linux Architecture

리눅스의 구조의 핵심은 사용자 환경과 커널 환경의 분리이다.

안전한 실행 환경과 하드웨어 자원 효율화를 위해서 나뉜다.

1. User Space

유저가 사용하는 공간으로, 응용 프로그램, Shell,glibc가 사용된다.

glibc(C 라이브러리)에서는 프로그램들이 커널을 쉽게 사용하기 위한 open(), read(), printf() 같은 표준 API 포맷 및 시스템 콜 래퍼(Wrapper) 함수를 제공한다.

2. System Call Interface

사용자 공간과 커널 공간을 연결하는 **유일한** 창구이다.

하드웨어 자원에 대한 접근이 필요할 때(읽기/쓰기, 메모리 접근, 네트워크 할당 등) 시스템 콜을 호출한다.

    fork(), execve(), read(), write(), socket(), malloc() 이 대표적인 시스템 콜

3. Kernal Space

운영체제의 **핵심**. CPU **최고 권한 모드**에서 작동하며, 모든 하드웨어의 제어권을 갖는다.

- 프로세스 관리자: 프로세스/스레드 생성 및 종료, 스케쥴링

- 메모리 관리자: 물리/가상 메모리 관리, 각 프로세스마다 가상 메모리 공간 할당 및 각 메모리 영역 침범 방지, 메모리 영역 관리

- 가상 파일 시스템(VFS): 다양한 종류의 파일 시스템을 하부 구조와 관계없이, 응용 프로그램이 동일한 API로 다룰 수 있도록 인터페이스 추상화

- 네트워크 스택: 소켓 생성, 프로토콜 처리(TCP/IP 등), 패킷 라우팅, 방화벽(iptables, nftables) 제어 담당

- 디바이스 드라이버: 하드웨어 제어 코드가 담긴 모듈, 문자 장치, 블록 장치, 네트워크 장치 3가지로 나누어 구분

# Linux의 핵심 철학

**Everything is file**, 즉 모든 컴퓨터가 접근할 수 있는 것들(하드웨어 정보, 프로세스 정보, 시스템 매개변수 등)을 `/dev`, `/proc`, `/sys` 아래에 파일 형태로

추상화하여 일관된 방식으로 접근.

핵심 기능은 단일 주소 공간에서 실행되어 성능이 매우 높음.

`.ko`이라는 파일 형식으로 전체 시스템(커널)을 재컴파일하지 않고, 디바이스 드라이버나 파일 시스템을 로드/언로드할 수 있는 모듈화 기능 제공
