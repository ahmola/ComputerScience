# 컴퓨터공학 & 소프트웨어공학 통합 학습 로드맵

컴퓨터를 유기적으로 이해하기 위한 바텀업(Bottom-Up) 학습 정리.
하드웨어에서 출발해 소프트웨어 설계·개발 역량으로 올라가고, 그 앞뒤로 기획과 운영 맥락을 가볍게 덧붙인 구조입니다.

## 전체 흐름

```
0부. 기획 (가볍게)
      ↓
1부. 컴퓨터 공학 기반 (하드웨어 → 인프라)
      ↓
2부. 소프트웨어 설계·개발 역량 (본체)
      ↓
3부. 운영 (가볍게)
```

- **1~2부**가 이 로드맵의 본체이며 깊이 있게 다룹니다.
- **0부, 3부**는 엔지니어가 PM/SRE와 맥락을 공유할 수 있을 정도로, 흐름만 가볍게 짚습니다.

---

## [0부. 기획 — 가볍게 (무엇을 왜 만드는가)](https://github.com/ahmola/ComputerScience/blob/main/Planning.md)

1. 요구사항 분석 기초
   - 요구사항 정의, 우선순위화 개념
2. 도메인 모델링 기초
   - DDD 핵심 개념 (바운디드 컨텍스트, 유비쿼터스 랭귀지)

> 2부의 "시스템 아키텍처 설계"가 어디서 출발하는지 맥락을 잡아주는 역할.

---

## [1부. 컴퓨터 공학 기반 (하드웨어 → 인프라, 바텀업)](https://github.com/ahmola/ComputerScience/blob/main/ComputerSceinece.md)

1. 컴퓨터 구조
2. 운영체제 (리눅스)
3. 컴파일러
4. 네트워크
5. 분산시스템 기초
   - CAP 정리, 합의 알고리즘, 일관성 모델
6. 가상화 기술
   - 하이퍼바이저 기반 VM
   - 컨테이너 (리눅스 namespace/cgroup과 연결)
   - 오케스트레이션 (쿠버네티스 등)
7. IaC 기반 인프라 + CI/CD + 모니터링/옵저버빌리티

---

## [2부. 소프트웨어 설계·개발 역량 (본체)](https://github.com/ahmola/ComputerScience/blob/main/SoftwareDesign.md)

1. 알고리즘/자료구조
   - 1부 → 2부를 잇는 사고 도구로 앞단에 배치
2. 시스템 아키텍처 설계
   - API 설계 (REST/GraphQL/gRPC), 메시징/이벤트 기반 아키텍처 포함
3. 데이터베이스
4. 데이터 엔지니어링 — 가볍게
   - 캐싱, 검색엔진, 데이터 파이프라인 개념
5. 디자인 원칙 & 패턴
   - SOLID → GoF 패턴
6. 코드베이스 설계 (프론트엔드/백엔드)
7. 보안 기초
   - 인증/인가, OWASP 핵심, 암호학 기초
8. 소프트웨어 테스트
9. 코드 관리
   - Git, 코드 리뷰 문화
10. 문서화 & 개발 방법론
    - 스크럼/칸반 + ADR/RFC 작성법
11. 소프트웨어 생애주기
    - 배포, 유지보수, 기술 부채 관리

---

## 3부. 운영 — 가볍게 (배포 이후의 삶)

1. SRE 기초
   - 온콜, 인시던트 대응 개념
2. 성능 모니터링 & 최적화 기초
3. 스케일링 전략 기초
   - 수직/수평 확장, 샤딩 개념

---

## 작성 의도

- **0부 → 1부 → 2부 → 3부**의 순서는 "왜 만드는가 → 어떤 기계 위에서 → 어떻게 설계·구현하는가 → 배포 후 어떻게 운영되는가"라는 제품의 전체 생애주기를 따라갑니다.
- 1부 끝의 IaC/CI-CD/모니터링(인프라 관점의 관찰)과 3부의 SRE/운영(서비스 관점의 대응)은 한 세트로 자연스럽게 이어지도록 배치했습니다.
- 0부·3부는 "PM이 되는 법"이 아니라 "엔지니어가 기획·운영 영역과 대화할 수 있는 최소 맥락"을 목표로 가볍게 다룹니다.
